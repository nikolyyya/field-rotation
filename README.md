# Полевой журнал

Учебное веб-приложение для учёта полей, посевов и агрономических операций. Интерфейс написан на TypeScript и React. API на Express хранит записи в SQLite. Для графиков используется Recharts.

## Запуск в WSL

Понадобятся Node.js 18 или новее и npm. В рабочей папке выполните:

```bash
cd /home/veronika/university/field-rotation
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173) и зарегистрируйтесь. Команда запускает интерфейс Vite на порту 5173 и Express API на порту 3000.

Для запуска собранного приложения:

```bash
npm run build
npm start
```

Адрес собранного приложения — [http://localhost:3000](http://localhost:3000).

При переносе проекта на другую машину сначала установите зависимости командой `npm ci`. Для сборки модуля SQLite из исходников потребуются Python 3, `make` и компилятор C++.

## Работа с журналом

1. Добавьте поле с площадью в гектарах и типом почвы.
2. Внесите одну или несколько культур в справочник.
3. Создайте посев для поля и сезона. Укажите дату посева. Дату уборки и урожайность в тоннах с гектара можно добавить позже.
4. Запишите полевые работы. У операции есть вид, дата, поле и примечание. При необходимости привяжите её к посеву на том же поле.
5. В статистике выберите сезон для графика посевных площадей. Второй график показывает среднюю урожайность по годам с учётом площади каждого поля.

Один посев занимает всё поле и учитывается один раз за сезон. Сервер запрещает повторять культуру на одном поле в двух соседних календарных сезонах. Правило действует и при редактировании, и при добавлении записей за прошлые годы. Например, после пшеницы в 2025 году на 2026 год нужно выбрать другую культуру.

## Структура проекта

| Папка | Содержимое |
| --- | --- |
| `src/` | Формы, таблицы и графики |
| `server/` | JWT-аутентификация, API и схема SQLite |
| `shared/` | Типы записей и список видов операций |
| `data/` | База данных и ключ подписи JWT. Создаётся при первом запуске |

В базе пять таблиц — пользователи, поля, культуры, посевы и операции. Каждый аккаунт видит свои записи. Данные сохраняются между запусками.
